化學結構格式偵測與轉換工程入門
RDKit  實作與 torch molecule 學習路線
版本 0.1.0　　2026 年 11 月 6 日　　適合零基礎學生
你的第一個目標，是讓使用者上傳小分子結構檔案後，得到可檢查的結構圖、其他結構檔與性質表。本指南把
這個目標拆成可以執行、可以解釋、可以驗證的工程流程。先完成此流程，再決定是否需要機器學習模型。
元件 在本題負責甚麼
RDKit 讀寫分子、檢查價態、畫結構圖、計算描述符；第一版核心。
torch-molecule 用訓練好的模型做性質預測、分子表示學習或生成。
Torch Molecule Studio 使用者操作的應用層；真正原始碼取得後才可確認整合方式。
這次交付可以做甚麼
ChemBridge 是獨立可執行的原型，附有本機網頁介面、CLI、原始碼、範例、測試與 DeepSeek 提示詞。核
心轉換可在 CPU 執行，不需要 LLM 金鑰。它尚未整合到 Studio，也未完成任意化學文件或圖片辨識。
閱讀與操作順序
頁次 你要完成的事
2–3 安裝、跑乙醇範例，理解文字如何變成分子圖。
4–6 看格式偵測、錯誤處理、輸出與核心程式。
7–8 理解 torch-molecule，學會展示工程證據。
9–11 安排下一週工作，使用 DeepSeek 提示詞，建立 GitHub 並推送。

理解一個分子如何變成輸出
名詞 白話解釋
SMILES 用文字記錄原子和連接關係；CCO 表示乙醇。
RDKit Mol 電腦內的分子圖，包含原子、鍵及可用的結構資訊。
CSV 表格容器；必須找出其中真正存放結構的欄位。
描述符 descriptor 由結構計算或估計的數值，如分子量、HBD、TPSA。
最小核心程式
from rdkit import Chem
from rdkit.Chem import Descriptors, Draw, Lipinski
mol = Chem.MolFromSmiles("CCO")
assert mol is not None
print(Descriptors.MolWt(mol))
print(Lipinski.NumHDonors(mol))
Draw.MolToImage(mol).save("ethanol.png")
第一行轉換不是畫圖，而是先讀懂分子。assert 確認沒有解析失敗。接著才可計算分子量、數氫鍵供體、畫
圖。完整可執行範例在 scripts/first_steps.py。
本工具實際生成的乙醇 2D 結構圖。圖上省略部分碳與氫的標示，是化學骨架圖的慣例，不代表分子少了這些
原子。
已知乙醇結果：分子式 C2H6O；分子量約 46.069 Da；HBD=1；HBA=1。你應能指著程式說明這些數字如何
來，並把 CCO 改成 CCN 再觀察差異。

讓系統知道正在讀甚麼
可靠的自動偵測要同時看內容與解析結果。副檔名可以提供線索，但使用者可能改錯檔名；CSV 也可能同時含
兩種分子表示。
順序 實際策略
1 內容標記 TRIPOS、PDB records、SDF 的 $$$$、MOL 的版本標記與 M END。
2 表格與 schema 辨認 CSV/TSV 分隔符、JSON 容器，再核對結構欄位。
3 文字與副檔名 InChI= 前綴、SMILES/SELFIES 檔名；不足時試解析。
4 明確拒絕歧義 多個結構欄、含糊的括號文字或不明 schema，需要使用者指定。
核心程式在哪裡
chembridge/io.py 的 detect() 選讀取方式；parse_records() 逐筆建分子。_table_records() 處理表格欄位。
下列片段展示為何兩個候選欄位不會被默默選掉。
elif len(named) > 1:
    raise InputError("Multiple structure columns: "
        + ", ".join(h for h, _ in named)
        + ". Select --column (and optionally --column-format).")
你可以重現的三個案例
範例 預期結果
molecules.csv 偵測 CSV，使用 SMILES 欄，5 筆成功。
misnamed.csv 內容是 MOL；偵測 MOL 並記錄副檔名衝突。
ambiguous_columns.csv 同時有 smiles/inchi；先要求選欄，選 smiles 後成功。
未知欄名會取樣前 20 筆，以可解析率尋找唯一候選欄；80% 是本工具規則，不是模型信心。只含分子式、名
稱或 CAS 的表格通常不足以唯一還原結構，不能強行當成 SMILES。
SELFIES 與某些括號 SMILES 可能看起來相同；請明確指定格式。自動偵測是一套有範圍的工程規則，並非能
讀懂任意化學文件。

讀懂輸出與資訊保留
輸出 要看甚麼
properties.csv 可用 Excel 查看各分子的性質；欄位附單位。
molecules.json 成功分子的結構、性質、來源 metadata、警告及檔案路徑。
PNG 與 SVG 預設前 100 個成功分子的 2D 圖；用副本繪製。
MOL SDF SMI InChI SELFIES 交給其他化學工具使用；各格式能承載的資訊不同。
errors 與 export_errors 原文、來源記錄索引及失敗原因；不要只檢查成功圖像。
manifest 與 original_input 偵測理由、版本、計數、SHA-256、耗時，以及原始輸入。
兩個成功分子的實際數值
性質 乙醇 阿士匹靈
分子式 C2H6O C9H8O4
分子量 Da 46.069 180.159
HBD 1 1
HBA 1 3
TPSA Å² 20.23 63.60
QED 0.407 0.550
HBD 是氫鍵供體計數；HBA 是受體計數。TPSA 描述極性表面積；RDKit logP 是模型估計。QED 是 drug-
likeness 描述，不能當作藥效、安全性或能否成藥的結論。
 甚麼會保留甚麼不能保證
本版不去鹽、不中和、不移除重複分子、不做互變異構體標準化。SDF/MOL 有原始座標時保留；無座標時生
成 2D。SMILES 不儲存原始 3D 座標，標準 InChI 亦可能正規化部分資訊。原檔備份與 JSON metadata 有助
追溯，但不能把所有格式轉換稱為普遍無損。

ChemBridge 0.1.0   6
  工程入門 /  06
跟著核心程式看完整邏輯
檔案與函式 負責甚麼
io.py  load_text decode_bytes 讀取文字、BOM 編碼及 gzip，限制檔案大小。
io.py  detect 選擇解析器，回傳理由、方法與警告。
io.py  parse_records 逐筆解析與驗證；失敗資料仍保留。
pipeline.py  properties 計算描述符，沒有呼叫 LLM 或訓練模型。
pipeline.py  convert_file 串起流程、寫出檔案、記錄 manifest。
__main__.py 與 app.py CLI 與本機介面，共用同一核心流程。
讀取後才產生標準表示及數值
mol = record.mol
smiles = Chem.MolToSmiles(
    mol, canonical=True, isomericSmiles=True)
props = properties(mol)
export_mol = Chem.Mol(mol)
isomericSmiles=True 讓可用的立體與同位素資訊進入輸出。建立副本是為了讓匯出和畫圖的座標操作不改動
原始分子。Canonical 字串是 RDKit 的正規表示，不能取代完整化學身分政策。
 日後給Studio 呼叫的入口
from chembridge import convert_file
manifest = convert_file(
    "uploaded_file.sdf", "new_job_directory",
    outputs="json,csv,png,sdf")
Studio 的後端只需重用此入口，前端顯示偵測、選欄、結果與錯誤。這是可整合的界面；真正 Studio 的路
由、登入、資料儲存與框架，必須讀到其原碼後才能修改。
完整來源記錄數應等於成功數加失敗數。CLI 退出碼 0 表示全部成功；1 表示資料／輸出有失敗且已產生報
告；2 表示輸入、設定或檔案層級問題。

  工程入門 /  07
 用這個題目學torch molecule
torch-molecule 的價值在模型工作流程。它接受分子表示，處理圖特徵、訓練或載入模型，再輸出預測、向
量或新分子。你不必先學完所有模型，才開始做檔案轉換。
目錄 初學者先看甚麼
base 模型共同設定、device、保存／載入及 fitted 檢查。
predictor 先看 GNNMolecularPredictor 的 fit() 與 predict()。
utils/graph graph_from_smiles：原子特徵、連接關係、鍵特徵。
datasets 讀取目標與來源，理解切分；標籤和單位不可省略。
encoder generator nn 向量表示、分子生成與神經網路元件，後續再深入。
圖模型讀甚麼
graph_from_smiles() 走訪每個原子與每條鍵。N 個原子對應 N 列原子特徵；E 條化學鍵加入兩個方向，所以 
edge_index 的形狀是 [2, 2E]。這個圖資料不是 PNG 圖片。
先明確定義預測任務
需要預測甚麼？標籤從哪裡來？單位是甚麼？checkpoint 適用哪些分子？只有這些確定，才應接模型。本包 
model_adapter.py 只是把成功 SMILES 依 ID 順序交給已有 predictor，未執行真正模型推論。
切分方式 你要理解的差別
random 隨機分列；重複結構可能跨集合。
scaffold 依骨架分組，檢查對未見骨架的泛化。
butina 依指紋相似度聚類，整組分配。
size 按重原子數分開，檢查尺寸外推。
此次上游快照的 train_test_split 回傳兩份 train/holdout。若 holdout 用來選模型，就應另留最終 test；不能
用同一份報告「未碰過」的測試分數。詳細讀碼順序與固定 commit 在 
TORCH_MOLECULE_SOURCE_MAP_zh.md。

git commit -m "Add chemical structure conversion MVP"
$repo = "CHANSingYeungSunny/chem-structure-converter"
gh repo create $repo --private --source . --remote origin
git push -u origin main
gh repo view --json nameWithOwner,url,isPrivate
git rev-parse HEAD
git ls-remote origin refs/heads/main
預設 private；若已有明確公開要求則採用 public。名稱被佔用時不可覆寫不相關 repo，可建立日期尾綴的新
名稱。記錄真實 URL、visibility、branch 與 commit SHA，本機 HEAD 要和遠端 main 一致。
 全新clone 是最後驗收
到另一個新目錄 clone，依 README 重建環境、跑 demo 和 pytest，再記錄結果。原工作區成功不等於遠端
可重現。執行者須回傳 clone 後的真實證據。
